# Architecture

> 10,000 ft view. For app composition see [src/mcp_toolkit/apps/server/APP.md](src/mcp_toolkit/apps/server/APP.md). For domain detail, see each `DOMAIN.md`.

## What it is

A Python framework. Users instantiate `MCPToolkit`, register tools against it (with group + scope metadata), and call `.build_app()` to get a runnable MCP server (FastMCP under the hood) with bearer auth, Prometheus metrics, Grafana dashboard generation, and multi-tenant access baked in.

## Two surfaces, one core

```
Library surface             Service surface
(your app code)             (deployed MCP server)
─────────────────           ──────────────────────
@toolkit.tool(...)          HTTP / stdio
        │                           │
        ▼                           ▼
   MCPToolkit ──── build_app ──► FastMCP app
        │                           │
        ▼                           ▼
   registry/                   apps/server/
   auth/                       (transport + middleware)
   observability/
   tenancy/
```

The framework's public API is the **library surface**. The **service surface** is what users deploy. Both live in this repo; `apps/server/` composes the domains into the runnable service.

## Golden path (service surface)

```
HTTP request
  → apps/server         (transport, routing, FastMCP wire)
  → domains/auth        (validate bearer, resolve scopes + tenant)
  → domains/tenancy     (bind tenant context)
  → domains/registry    (filter tool discovery by scope)
  → tool dispatch
  → domains/observability (record metric, emit event)
  → HTTP response
```

## Shared

`src/mcp_toolkit/shared/` — config loader, structured logger, error taxonomy, HTTP client factory, optional OpenTelemetry hooks. Imported by domains and apps. Never imports from them.

## One-click infrastructure

`deploy/observability-stack/` is a `docker compose` bundle (Prometheus + Grafana + the MCP server image) that comes up with `make stack-up`. Grafana is pre-provisioned with dashboards generated from the toolkit's metric registry at build time — so the dashboard always matches what the code actually emits.

## Domain dependency graph

```
apps/server ──► domains/auth ──► domains/tenancy
apps/server ──► domains/registry
apps/server ──► domains/observability
domains/observability ──► domains/tenancy   (per-tenant metric labels)
domains/registry ──► domains/auth           (scope→group resolution)
domains/* ──► shared/
```

No circular deps. Cross-domain edges are minimal and documented in each importer's `DOMAIN.md`.

## Scaling model

Stateless pods behind Knative autoscaler. Shared state (token store + quota counters + Prometheus aggregation) lives in Upstash Redis + Prometheus respectively. Concurrency-target autoscaling. See [docs/KNATIVE.md](docs/KNATIVE.md).

## Decision Log

**2026-05-17: Library + service in one repo.**
Users who want only the library import `mcp_toolkit`. Users who want the whole stack run `deploy/observability-stack/`. Single repo so the dashboard generator and the metrics it documents can never drift.

**2026-05-17: FastMCP underneath, not replaced.**
FastMCP owns transports, MCP wire protocol, schema generation. `mcp-toolkit` adds the missing batteries (auth-scoping, observability, multitenancy, dashboards). Re-implementing FastMCP would triple scope.

**2026-05-17: Domain-level metric/dashboard ownership.**
Each domain owns the metrics it emits; `domains/observability` provides the registration API, not the metrics themselves. Dashboards are generated by walking the registry. Tradeoff: more boilerplate at the domain edge; gain: no global metric catalogue to drift.

**2026-05-17: Multitenancy is opt-in, layered above auth.**
Single-tenant deployments (`TENANT_STRATEGY=single`) skip the tenancy domain's middleware entirely — zero overhead. Multi-tenant deployments pick a resolver (header / subdomain / token-claim). Tenant boundary lives at observability *and* tool-discovery layer.
